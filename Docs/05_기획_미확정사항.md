## B. 아직 안 정해진 것

### B1. 드래그 "1회차인데 엔딩기물, 떡절구"
6-3 "조건에 맞지 않는 기물(1회차인데 엔딩기물, 떡절구, 이미 점유된 기물)". '1회차'의 뜻 — 1회차엔 떡절구에 **아무도(옥토끼 포함)** 못 앉는지, 주인 아닌 요괴만인지.
- **지금 구현:** 주인(옥토끼)만 앉을 수 있음. 다른 요괴 → (x).

### B2. "엔딩기물 2개"의 정체
8장 "엔딩기물 2개는 전부 떡절구의 레벨에 따른다" — 정의된 엔딩기물은 떡절구 하나. 다른 요괴 엔딩기물이 나올 예정인지, 다른 뜻인지.  
(MVP는 떡절구만 집중)

### B3. 오프라인 중 추가 보관(오버플로우) 판정
방치 수익 `min(보관량, …)`의 "보관량"이 오버플로우 포함인지.
- **지금 구현:** 오프라인도 온라인과 똑같이 판정.

## C. v1.3 — 기획은 정해졌는데 코드가 아직 안 따라간 것 (2026-10-08 대조)

`[기획문서] 한폭요괴 1.0.docx`("기물·공양간·나루터 통합 기획 v1.3")를 코드와 전체 대조한 결과.
**B처럼 결정이 필요한 게 아니라, 이미 결정된 걸 아직 안 만든 것** — 구현되면 여기서 지운다.

### C1. 황금재료 재설계 — ✅ 구현됨 (2026-10-12)
기획서: 황금쌀·황금꿀 폐지 → 산나물·약재·고추·해산물·새고기·새알 **6종 각각 1%**로 황금 버전이 나옴(절벽의 약초골·파도치는 섬 전용), 섞인 요리는 황금 요리.
- `Enums.SpecialItemId`에 6종 추가(기존 2종은 순서 유지 — 세이브 호환). `CookingSession.TryGoldenOf`/`TryBaseOf`로 재료↔황금 양방향 매핑.
- `PropCatalog.ApplyGoldenUpgrade`: 목적지(`destinations.goldenChance`, 이미 시트에 절벽의 약초골·파도치는 섬만 1.0으로 들어 있던 값)에서 뽑힌 재료를 그 확률로 황금 버전으로 승급 — `PropProduction.Produce`에서 드롭 롤 직후 호출. 시트 쪽 추가 작업 없이 기존 destinations 값으로 바로 동작.
- 이름·설명(`CodexDescriptions.SpecialItemName`)·요리책 칸(`CodexScreen`)·기물 창 미리보기(`PropPanel.DropLine`)도 6종 전체로 일반화.
- **남은 것(시트):** 기존 `props.json` dropTables의 전역 `Gather`/`Hunt` 테이블에 남아 있는 `GoldenRice`/`GoldenHoney` weight=1 행은 옛 방식(목적지 무관 전역 확률) 잔재 — 지워도 되고 기존 보유분 호환용으로 남겨도 됨(A3 "기존 황금쌀·황금꿀 보유분 처리" 결정과 연결).
- 요리판 버프 10분·3배속으로 바꾸는 건 `game_settings.json`의 `goldenBuffMinutes`·`goldenSpeedMul` 시트 값만 고치면 됨(엔지니어링 아님).

### C2. 옥토끼 NPC화 — 일부 반영 (2026-10-12)
기획서: 옥토끼는 슬롯에서 빠지는 NPC. 친밀도 100 고정, 기력 바만 있음, 떡절구만 찧음, 윷놀이에서 빠짐.
- **친밀도 100 고정 — ✅**: `CharacterAgent.ApplyDefaultStatsFromData`(새 게임) · `ApplySaveSnapshot`(로드, 옛 세이브 값도 매번 100으로 덮음). 먹이기·윷 둘 다 이미 제외라 이 뒤로 바뀔 경로 없음.
- **윷놀이 제외 — ✅**: `YutScreen.cs` 팀 구성(`BeginMatch`)에서 옥토끼를 뺌 — 말로 뛰지 않고 잡히지도 않음. 다만 "윷이군, 다시" 같은 던지기 해설(말풍선 규칙 2번, `RabbitThrowLine`)은 의도된 기존 기능이라 유지 — `HandlePiecesChanged`에서 옥토끼를 항상 동(東) 완주 줄에 있는 것으로 쳐서 해설 앵커만 살려둠. 결과적으로 "저 친구 완주할 수 있어요"류 해설 쪼로 고정.
- **공양(먹이기) 완전 차단 — ✅**: 그릇 말풍선/놀고있는 요괴 탭(지난 세션)에 더해 `CharacterAgent.TryFeed`/`TryFeedWater` 자체에서 막음(`FeedBlock.NotFeedable`) — 상세 화면의 자체 먹이기 버튼(FeedPopup 경유 안 함)까지 전부 커버.
- **슬롯 바 표시 — 미반영(의도적 보류)**: `CharacterSummon`(소환 가능 여부 판정)은 원래부터 옥토끼 존재 여부와 무관해서 "슬롯에서 뺀다"가 소환 로직엔 영향 없음. 다만 `GameHud`의 상단 슬롯 바엔 옥토끼 칩이 그대로 남아 있고, 그 칩 위에 버드나무 일괄수거 버튼이 얹혀 있어(`GameHud.cs:495`) — 칩을 완전히 빼려면 그 버튼을 다른 자리로 옮겨야 함. 비주얼 전용 변경이라 별도 확인 후 진행.
- `08` 문서 "기획 확인 필요 모음" 6번과 묶여 있었음 — 상세 화면·공양 가능 여부는 이제 해소.

### C3. 요리책 새 레시피 → 엽전 보상 — ✅ 구현됨 (2026-10-12)
기획서: 요리책에서 처음 발견한 레시피 칸마다 엽전 1개(미발견 76개 기준 최대 76개). `08` 문서 §6에도 이미 "엽전 표시가 붙은 칸(새 레시피) → 엽전 1개 받기"로 기록돼 있음.
- `CookingCodex`에 `claimed`(받은 칸) 별도 추적 추가 — `discovered`(발견)와 분리해서, 나가리로 발견이 풀렸다가 다시 발견해도 한 번 받은 칸은 또 안 줌("레시피마다 한 번" 보장). 세이브에 `codexClaimed`로 별도 저장.
- `CodexScreen`: 발견했지만 안 받은 칸에 "+1" 배지 표시, 탭하면 `GameEconomy.AddYeopjeon(1)` + 토스트 + 상세 팝업(기존 동작 그대로 유지).
- 엽전 수급처가 하나 늘었을 뿐 — A3 "엽전 수급처" 항목(출석·윷·새 레시피뿐, 업적 없음)은 그대로 유효.

### C4. 화면 감상(30초 UI 자동 숨김)

- **지금 코드:** 관련 로직 전혀 없음(검색 결과 없음).
